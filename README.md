# Mini NPU Simulator

패턴과 필터의 같은 위치 값을 곱하고 누적하는 MAC 연산을 Python 반복문으로 구현한 콘솔 프로그램입니다. 학습된 AI 모델이나 실제 NPU의 속도를 재현하는 프로그램은 아닙니다.

## 실행 방법

Python 3.8 이상과 표준 라이브러리만 사용합니다. 추가 패키지 설치는 필요 없습니다.

```bash
python main.py
```

1번은 3×3 필터 A, B를 각각 3줄 입력합니다. 각 줄에 숫자 3개를 공백으로 구분합니다. 필터 저장 결과를 확인한 뒤 패턴을 직접 입력하거나 생성된 Cross/X를 선택합니다. 숫자나 열 개수가 잘못되면 같은 행을 다시 입력합니다. 3개 행을 순서대로 받으므로 행 개수가 부족하면 다음 행을 계속 요청합니다.

2번은 main.py와 같은 폴더의 공식 `data.json`을 분석합니다. 제공받은 공식 데이터는 `data.json`으로 포함했습니다. 이 폴더의 `sample-data.json`은 프로그램 동작 재현을 위한 자체 생성 데이터이며 공식 데이터가 아닙니다.

```bash
python main.py --data sample-data.json
python main.py --data error-cases.json
python main.py --data data.json --repeats 1000
```

`--data`는 지정한 파일로 모드 2를 바로 실행합니다. 반복 횟수는 기본 1000회이며 10회 미만은 거절합니다. 실행 결과의 케이스별 점수, 판정, 총합, 성능 측정은 `reports/파일이름-report.json`에 저장됩니다.

## 구현 요약

- `validate_matrix`: N×N 형태, 숫자 자료형과 유한한 값 검증
- `normalize_label`: `+`, `cross`, `Cross` → `Cross`; `x`, `X` → `X`
- `mac_2d`: 이중 반복문으로 위치별 곱과 합을 누적
- `decide`: `abs(a-b) < 1e-9`이면 `UNDECIDED`
- `analyze`: `size_N_idx`에서 크기를 추출해 `size_N` 필터 선택
- `performance`: 파일 읽기, 출력, 데이터 변환을 제외하고 함수 호출 구간 측정

필터 구조는 `filters.size_5.cross`, `filters.size_5.x`와 같은 형태입니다. `size_13`, `size_25`도 동일합니다. 패턴은 `patterns.size_5_1.input`, `patterns.size_5_1.expected` 형식입니다. 필터·패턴 크기가 잘못되거나 expected 라벨이 알 수 없는 값이면 해당 케이스만 FAIL로 기록합니다. 필터 파일 자체를 읽을 수 없거나 patterns가 없는 경우에는 로드 오류를 안내합니다.

## 보너스 1: 메모리 접근 최적화

`flatten()`으로 N×N 배열을 길이 N²인 배열로 변환하고 `mac_1d()`가 단일 반복문으로 계산합니다. 2D와 1D는 같은 데이터, 같은 반복 횟수를 사용합니다. 변환과 워밍업은 측정에서 제외하고 측정 순서를 번갈아 실행합니다. 평균, 중앙값은 JSON 리포트에 기록되며 콘솔은 평균과 2D/1D 시간 비율을 표시합니다. 비율이 1보다 크면 해당 측정에서 1D가 빨랐다는 뜻입니다. 실제 성능 향상은 보장하지 않습니다.

## 보너스 2: 패턴 생성기

```bash
python main.py --generate 13
```

3 이상의 홀수 N을 받아 Cross와 X 배열을 JSON으로 출력합니다. Cross는 가운데 행·열, X는 양쪽 대각선을 1로 채웁니다. 짝수는 중심 정의의 모호함을 피하기 위해 거절합니다. 이 생성 함수는 사용자 입력 모드의 패턴 선택과 크기별 성능 분석에 재사용됩니다.

## 재현 절차

필터 A와 B에 다음 배열을 각각 입력합니다.

```text
0 1 0
1 1 1
0 1 0
```

```text
1 0 1
0 1 0
1 0 1
```

패턴에 X 배열을 입력하면 A 점수 1, B 점수 5, 판정 B가 예상됩니다. Cross 배열을 입력하면 A 점수 5, B 점수 1, 판정 A가 예상됩니다. 이는 재현 시 기대값이며 실제 실행 캡처를 대신하지 않습니다.

`sample-data.json`은 크기마다 Cross/X 각 1개로 총 6개입니다. 기대 결과는 총 6, PASS 6, FAIL 0입니다. `error-cases.json`은 위 6개에 동점, 크기 오류, 알 수 없는 라벨, 잘못된 패턴 키를 추가합니다. 기대 결과는 총 10, PASS 6, FAIL 4입니다.

## 결과 리포트

1. 제공된 공식 `data.json` 실제 실행 결과는 총 6개, PASS 3개, FAIL 3개입니다.
2. 자체 샘플 데이터의 기대값은 생성 규칙으로 계산한 결과이며 실행 완료 기록과 구별합니다.
3. Cross/X 샘플은 각 필터와 일치할 때 2N−1점, 반대 필터에는 중심 한 칸이 겹쳐 1점입니다.
4. expected의 `+`와 필터 키 `cross`를 그대로 비교하면 같은 뜻이어도 실패할 수 있습니다.
5. 따라서 판정과 expected를 Cross/X로 정규화한 뒤 비교합니다.
6. 부동소수점은 0.9와 같은 값을 정확히 저장하지 못해 작은 차이가 발생할 수 있습니다.
7. 절대 점수 차가 1e-9보다 작으면 UNDECIDED로 처리합니다.
8. UNDECIDED는 expected Cross/X와 일치하지 않으므로 FAIL이며 실패 목록에 이유를 남깁니다.
9. 작은 점수 차를 epsilon으로 묶어도 모든 FAIL이 없어지는 것은 아닙니다.
10. 크기·키·라벨 오류는 데이터/스키마 문제로 분류합니다.
11. 정상 입력의 수작업 점수와 MAC 점수가 다르면 반복문 인덱스·누적 로직 문제를 확인합니다.
12. 거의 같은 점수의 판정 차이는 수치 비교 정책을 확인합니다.
13. N×N 필터 하나에는 N²번의 곱셈과 N²번의 누적 덧셈이 필요합니다.
14. 표의 9, 25, 169, 625는 한 필터의 MAC 횟수이며 두 필터 판정에는 2N² MAC이 필요합니다.
15. 이중 반복문의 각 위치를 한 번 방문하므로 시간 복잡도는 O(N²)입니다.
16. 1D 구현도 원소 N²개를 순회하므로 시간 복잡도는 O(N²)이며 인덱싱 비용이 달라집니다.
17. 1D 변환은 O(N²) 시간과 추가 공간을 사용하며 반복 연산에 재사용할 때 유리할 수 있습니다.
18. 성능 표에는 3×3, 5×5, 13×13, 25×25의 실제 측정 평균이 출력됩니다.
19. 짧은 연산의 측정에는 타이머 비용, 운영체제 스케줄링, CPU 상태가 영향을 줍니다.
20. 따라서 시간 비율이 정확히 N² 비율과 같거나 매 측정마다 단조 증가한다고 보장하지 않습니다.

## 제출 안내

`main.py`, 이 README, 공식 `data.json`과 실행 후 생성된 `reports/`를 저장소에 올립니다. 과제 원문에는 스크린샷 필수 조건이 없지만 실행 화면을 요구받으면 실제 터미널에서 모드 1 결과, 모드 2 케이스 결과·요약, 성능 표를 캡처합니다. 자체 샘플과 오류 데이터는 재현 자료로 함께 올릴 수 있습니다.


## 공식 데이터 실제 실행 결과

Python 3.12.14 / Windows, 각 크기 1000회 반복 측정. 전체 출력은 [실행 로그](reports/data-console.txt), 기계 판독 결과는 [JSON 리포트](reports/data-report.json)에 있습니다.

| 케이스 | Cross 점수 | X 점수 | 판정 | expected | 결과 |
| --- | --- | --- | --- | --- | --- |
| size_5_1 | 0.9 | 0.8999999999999999 | UNDECIDED | X | FAIL |
| size_5_2 | 8.9 | 0.1 | Cross | Cross | PASS |
| size_13_1 | 0.3 | 14.70000000000001 | X | X | PASS |
| size_13_2 | 7.499999999999997 | 7.5 | UNDECIDED | Cross | FAIL |
| size_25_1 | 4.9 | 4.899999999999999 | UNDECIDED | X | FAIL |
| size_25_2 | 52.9 | 0.1 | Cross | Cross | PASS |

`size_5_1`, `size_13_2`, `size_25_1`은 점수 차이가 1e-9보다 작아 동점으로 판정됐습니다. 필터 중심값과 가중치에 의해 수학적으로 같은 점수가 나며, 부동소수점 누적으로 작은 차이가 생깁니다. 라벨과 스키마는 정상입니다. expected에 맞추려고 동점 규칙이나 제공 데이터를 바꾸지 않았습니다. 이는 실행 오류가 아니라 정해진 판정 정책과 expected의 차이입니다.

| 크기 | 2D 평균 ms | 1D 평균 ms | MAC 횟수 | 2D/1D |
| --- | --- | --- | --- | --- |
| 3×3 | 0.001931 | 0.001138 | 9 | 1.696 |
| 5×5 | 0.003981 | 0.002270 | 25 | 1.754 |
| 13×13 | 0.017569 | 0.011964 | 169 | 1.468 |
| 25×25 | 0.053250 | 0.044048 | 625 | 1.209 |

실측에서는 1D가 빨랐으며 양쪽 모두 O(N²)입니다. 생성 패턴의 동일 배열을 비교했고 변환 시간은 제외했습니다. 실행 환경에 따라 측정값은 달라집니다. 자체 오류 데이터 10개에서는 정상 6개 PASS, 의도적 오류 4개 FAIL로 집계됐습니다.
